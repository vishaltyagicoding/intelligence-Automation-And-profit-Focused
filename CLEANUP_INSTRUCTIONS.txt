WHAT WAS FIXED (3-LAYER DEFENSE SYSTEM)
================================================================================

LAYER 1 - Calculator Level (reversal_calculator.py):
- _emit_reversal() now checks if last reversal has SAME direction
- If consecutive signal detected (BUY→BUY or SELL→SELL), SKIP and log warning
- This catches calculator bugs at the SOURCE before they reach the database

LAYER 2 - Task Level (tasks.py):
- _save_zones_to_db() tracks last saved label from DB
- Tracks last saved label WITHIN the current batch
- Compares each new signal against BOTH DB and batch history
- Skips if same label (enforces alternation during batch processing)

LAYER 3 - Database Level (models.py):
- Alternation constraint in ReversalZone model (already existed)
- Final safety net if Layers 1-2 somehow fail

RESULT: TRIPLE PROTECTION
- Calculator won't emit consecutive signals (Layer 1)
- Task won't save consecutive signals (Layer 2)  
- Database won't accept consecutive signals (Layer 3)
