═══════════════════════════════════════════════════════════════════════════════
ROOT CAUSE
═══════════════════════════════════════════════════════════════════════════════

The 30-minute Celery task 'update-all-recent-signals-every-15min' is STILL RUNNING
on the production server, even though we disabled it in the code.

WHY IT'S STILL RUNNING:
1. Task was created in database BEFORE our code deployment
2. Our code changes only prevent NEW task creation
3. EXISTING task in database is still active and running every 15-30 minutes
4. Task recalculates signals from historical data
5. Task sends emails 30-45 minutes after signal appears

═══════════════════════════════════════════════════════════════════════════════
WHY DJANGO SIGNAL HANDLER ISN'T WORKING
═══════════════════════════════════════════════════════════════════════════════

The Django signal handler (reversal_zones/signals.py) IS correctly configured:
✅ Registered in apps.py
✅ Triggers on post_save for ReversalZone model
✅ Sends email via notify_signal_subscribers()
✅ Uses created=True to only send on NEW signals

BUT: The Celery task is ALSO saving signals to the database, which triggers
the Django signal handler. This creates a race condition:

SCENARIO 1 (What should happen):
  07:15:00 - WebSocket detects signal
  07:15:00 - Signal saved to DB (created=True)
  07:15:01 - Django signal handler sends email ✅
  
SCENARIO 2 (What's actually happening):
  07:15:00 - WebSocket detects signal
  07:15:00 - Signal saved to DB (created=False, update_or_create)
  07:15:01 - Django signal handler skips (created=False)
  07:45:00 - Celery task runs
  07:45:00 - Celery task recalculates signal from history
  07:45:00 - Celery task saves signal (created=True or update)
  08:00:00 - Email sent (45 min late!) ❌

═══════════════════════════════════════════════════════════════════════════════
THE PERMANENT FIX
═══════════════════════════════════════════════════════════════════════════════

We MUST manually disable the Celery task on the server. The task exists in the
database and will keep running until we explicitly disable it.

STEPS TO FIX (See MANUAL_FIX_COMMANDS.txt for detailed instructions):

1. SSH to server: ssh -i smartriskfx-singapore.pem ubuntu@13.250.19.107
2. Navigate to project: cd ~/smartrisk
3. Open Django shell: sudo docker-compose exec django python manage.py shell
4. Run Python code to disable task:
   
   from django_celery_beat.models import PeriodicTask
   task = PeriodicTask.objects.get(name='update-all-recent-signals-every-15min')
   task.enabled = False
   task.save()
   exit()

5. Restart Celery: sudo docker-compose restart celery_beat celery_worker
6. Verify: sudo docker-compose ps

   - This prevented NEW task creation
