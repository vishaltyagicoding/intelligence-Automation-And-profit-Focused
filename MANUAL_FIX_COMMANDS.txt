STEP 3: Disable the Celery Task
═══════════════════════════════════════════════════════════════════════════════

sudo docker-compose exec django python manage.py shell

Then paste this Python code:

from django_celery_beat.models import PeriodicTask

# Find and disable the task
try:
    task = PeriodicTask.objects.get(name='update-all-recent-signals-every-15min')
    print(f"Found task: {task.name}")
    print(f"Currently enabled: {task.enabled}")
    print(f"Task: {task.task}")
    
    # DISABLE IT
    task.enabled = False
    task.save()
    
    print("\n✅ TASK DISABLED!")
    print("Emails will now be sent INSTANTLY via Django signal handler")
except PeriodicTask.DoesNotExist:
    print("Task not found (may already be deleted)")

# List all signal tasks
print("\n📋 All signal-related tasks:")
for t in PeriodicTask.objects.filter(task__icontains='signal'):
    status = "ENABLED" if t.enabled else "DISABLED"
    print(f"  [{status}] {t.name}")

exit()

WHY THIS FIXES THE PROBLEM
═══════════════════════════════════════════════════════════════════════════════

OLD FLOW (BROKEN):
  1. WebSocket detects signal at 07:15
  2. Signal saved to database
  3. Django signal handler tries to send email → FAILS (task conflict)
  4. 30-minute Celery task runs at 07:45
  5. Task recalculates signals from history
  6. Task sends email at 08:00 (45 min late!)

NEW FLOW (FIXED):
  1. WebSocket detects signal at 07:15
  2. Signal saved to database
  3. Django signal handler sends email INSTANTLY at 07:15
  4. User receives email within 1-2 seconds ✅
