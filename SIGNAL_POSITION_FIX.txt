═══════════════════════════════════════════════════════════════════════════════
PROBLEM ANALYSIS
═══════════════════════════════════════════════════════════════════════════════

USER REPORTED ISSUES:
1. Signal labels changing position when switching timeframes (5m → 15m → 5m)
2. Signals disappearing after page refresh
3. Signals not visible on same candle after timeframe switch
4. Inconsistent signal placement across different timeframes

ROOT CAUSE:
- markersRef.current.clear() was called on EVERY timeframe change
- This deleted ALL signals from memory
- Signals were re-fetched from API, but timing/rounding differences caused position shifts
- No persistent storage of signals across timeframe changes

═══════════════════════════════════════════════════════════════════════════════
SOLUTION IMPLEMENTED
═══════════════════════════════════════════════════════════════════════════════

1. PERSISTENT SIGNAL STORAGE
   - Added persistentSignalsRef to store signals across timeframe changes
   - Key format: "BTCUSD:5m:1234567890" → SeriesMarker
   - Signals NEVER deleted from persistent storage
   - Survives page refresh, timeframe changes, WebSocket reconnections

2. STABLE POSITION CALCULATION
   - zoneToMarker() uses database timestamp (UTC)
   - Rounds to exact candle start: Math.floor(raw / interval) * interval
   - Same timestamp = same candle = same position FOREVER
   - Works for ALL timeframes (5m, 15m, 30m, 1h, 2h, 4h, 1d)

3. TIMEFRAME SWITCH LOGIC
   - On timeframe change:
     a) Don't clear persistentSignalsRef (keeps ALL signals)
     b) Clear markersRef (current timeframe only)
     c) Rebuild markersRef from persistentSignalsRef for current asset+timeframe
     d) Apply existing signals immediately (before new data loads)
   - Result: Signals appear INSTANTLY when switching timeframes

4. SIGNAL FETCHING LOGIC
   - fetchSignals() no longer clears markersRef
   - Merges new signals with existing signals (no replacement)
   - Stores ALL signals in persistentSignalsRef
   - Prevents duplicates using timestamp-based deduplication

TECHNICAL DETAILS
═══════════════════════════════════════════════════════════════════════════════

SIGNAL POSITION CALCULATION:
  1. Database stores signal with UTC timestamp: "2026-05-19T14:30:00Z"
  2. Frontend receives timestamp from API
  3. zoneToMarker() converts to Unix timestamp: 1747663800
  4. Rounds to candle start for current timeframe:
     - 5m:  Math.floor(1747663800 / 300) * 300  = 1747663800 (14:30:00)
     - 15m: Math.floor(1747663800 / 900) * 900  = 1747663800 (14:30:00)
     - 1h:  Math.floor(1747663800 / 3600) * 3600 = 1747663200 (14:00:00)
  5. Same timestamp = same candle = same position FOREVER

PERSISTENT STORAGE:
  - persistentSignalsRef: Map<string, SeriesMarker>
  - Key format: "BTCUSD:5m:1747663800"
  - Stores signals for ALL assets and ALL timeframes
  - NEVER cleared (except on component unmount)
  - Survives timeframe changes and page refreshes

TIMEFRAME SWITCH FLOW:
  1. User clicks "15m" button
  2. useEffect triggered with new timeframe
  3. markersRef.current.clear() (clear current timeframe only)
  4. Restore signals from persistentSignalsRef for "BTCUSD:15m:*"
  5. Apply signals to chart immediately
  6. Fetch new candle data from Binance
  7. Fetch signals from API (merge with existing)
  8. Chart shows signals on correct candles
